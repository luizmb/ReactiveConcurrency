# Monad Transformers

How ReactiveConcurrency stacks its effects (``DeferredTask``, ``DeferredStream``, ``Publisher``)
with the FP library's data structures — and why the matrix is intentionally one-directional.

## Overview

A *monad transformer* combines two type constructors so their capabilities compose. RC ships
transformers between its three **effects** and the FP `DataStructure` types (`Either`, `Result`,
`Optional`, `Array`, `Validation`, `Reader`, `Writer`, `Stateful`), in the `ReactiveConcurrencyTransformers`
product, with symbolic operators in `ReactiveConcurrencyOperators`.

The model is FP 3's: every stack is its own struct named `OuterTInner`, wrapping the whole nested
value. `DeferredTaskTResult<E, A>` wraps `DeferredTask<Result<A, E>>`, `ReaderTPublisher<Env, E, A>`
wraps `Reader<Env, Publisher<A, E>>`. A plain `DeferredTask<Result<A, E>>` is just a `DeferredTask`
(its operators are the `DeferredTask` ones); the stack behaviour only exists once you wrap it.

```swift
let user: DeferredTask<Result<User, APIError>> = api.fetchUser(id)

// Lift in with the property named after the outer type, work on the inner value, leave with `rawValue`.
let name = user.deferredTaskT
    .flatMap { user in api.fetchProfile(user.profileID).deferredTaskT }
    .map(\.displayName)
    .rawValue                        // DeferredTask<Result<String, APIError>>
```

Every stack has `rawValue`, `init(_:)` / `init(rawValue:)`, `map` / `fmap`, `pure`, `apply`,
`liftA2`, `seqRight`, `seqLeft`, and on monad stacks `flatMap`, `bind`, `kleisli` / `kleisliBack`.
The operators are the usual ones on the stack type: `<£>`, `<&>`, `£>`, `<£`, `<*>`, `*>`, `<*`, and
on monad stacks `>>-`, `-<<`, `>=>`, `<=<`. Lifting properties: `.deferredTaskT`, `.deferredStreamT`,
`.publisherT`, `.readerT`, `.statefulT`. Each stack also has an escape hatch over the whole nested
value, named as in Haskell (`mapExceptT`, `mapMaybeT`, `mapWriterT`, `mapReaderT`, `mapStateT`,
`mapPublisherT`, `mapDeferredStreamT`, `mapDeferredTaskT`).

On Apple platforms FP declares Combine stacks with some of the same names (`PublisherTResult`,
`ReaderTPublisher`, …). Code that only lifts with `.publisherT` / `.readerT` never spells the type;
where you do, qualify it: `ReactiveConcurrencyTransformers.PublisherTResult<Never, MyError, Int>`.

The stacks are generated by `Scripts/GenerateTransformers.swift`; see CONTRIBUTING.

## The matrix

Monad stacks are lawful monads, and their `<*>` is derived from `>>-` (`ap`), so the two always
agree: on a short-circuit (`.failure`, `.left`, `nil`) the right-hand effect never runs. Verified by
the `TransformerLawTests` (left/right identity, associativity, `>=>`/`<=<` consistency, `<*>` == `ap`).

| Direction | Stacks | Functor | Applicative | Monad |
|---|---|---|---|---|
| **Effect-outer, structure-inner** | `{DeferredTask, DeferredStream, Publisher}T{Either, Optional, Result}` | ✓ | ✓ | ✓ |
| Effect-outer, Writer-inner | `…TWriter` | ✓ | ✓ | ✓ (combines logs) |
| Effect-outer, Array-inner | `…TArray` | ✓ | ✓ (cartesian) | — |
| Effect-outer, Validation-inner | `…TValidation` | ✓ | ✓ (accumulates) | — |
| **Reader-outer, effect-inner** | `ReaderT{DeferredTask, DeferredStream, Publisher}` | ✓ | ✓ | ✓ |
| Stateful-outer, effect-inner | `StatefulT{DeferredTask, DeferredStream, Publisher}` | ✓ | ✓ | — |

`DeferredTaskTOptional` and `DeferredTaskTResult` also have a lawful, left-biased `Alternative`
(`alt` / `<|>`) and a concurrent `race`. `PublisherTOptional` / `PublisherTResult` have `zipAlt`, a
positional element-wise choice that is not a lawful Alternative (no `<|>`).

## Why some stacks have no monad

RC follows FP 3 and takes Haskell as the source of truth:

- **`Array` inside an effect is `ListT` done wrong.** `DeferredTask<[A]>` has no lawful monad unless
  the effect is commutative, so `…TArray` is applicative-only (like Haskell's `Compose`).

- **`Validation` is Applicative-only.** Its `flatMap` would short-circuit on the first failure while
  its `apply` accumulates errors — violating the Applicative/Monad consistency law. Convert to
  `Result`/`Either` for short-circuit sequencing.

- **`Stateful` threads its state outside the effect** (`(inout S) -> DeferredTask<A>`), so bind
  cannot see a state produced inside the effect: `StatefulT…` is applicative-only. Use
  `ReaderT…` for monadic chaining with a read-only environment.

And why some directions are absent:

- **Container-outer / effect-inner** (e.g. `Either<L, DeferredTask<A>>`) is **not provided**: you
  cannot synchronously extract an *async* result to drive the outer structure's `flatMap`, so no
  lawful `Monad` exists — only Functor/Applicative, which the effect-outer direction already covers.

- **Writer-outer / effect-inner** (`Writer<W, DeferredTask<A>>`) is **not provided**: with the log
  *outside* the effect, `bind` cannot observe the continuation's log without running the effect. RC
  instead uses **effect-outer** `…TWriter` (`DeferredTask<Writer<W, A>>`), where `bind` combines
  `w1 <> w2` inside the effect — the lawful shape.

- **Effect-outer / Reader-inner** (`DeferredTask<Reader<Env, A>>`) is **not provided**: use
  `ReaderT…` instead, which defers the effect until the environment is supplied.

## Streams: `<*>` is the cartesian product

`DeferredStream` and `Publisher` bind with ordered concat, and their applicative is `ap`, derived
from it: `fs <*> xs` applies each function, in order, to every value. The stream stacks inherit that.
For positional, ZipList-style pairing use `zip`.

## Traversals

Turn a container of effects into an effect of a container: `sequence…` and `traverse…`. `DeferredTask`
runs them sequentially; `DeferredStream` and `Publisher` follow their applicative, emitting every
combination of one value per input, in order (the first input varies slowest).
